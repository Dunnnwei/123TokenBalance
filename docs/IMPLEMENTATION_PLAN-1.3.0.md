# 1.3.0 刷新可靠性与账号恢复实施方案

日期：2026-10-21。基线：1.2.0。用户日常目录：`D:\Program Files\123TokenBalance`。

## 目标与已确认原因

1. `browserRead` 要求登录窗口一直存在，关闭窗口或重启后持久会话也不能自动刷新。改为按账号恢复持久会话、创建不抢焦点的后台网页、等待动态额度就绪，并在结束后释放后台窗口。保留三账号并发及同账号请求合并。
2. 抓取保存永远创建新 UUID。增加详情、编辑和菜单的「程序内打开并重新抓取」，以 UUID/revision 更新原记录；首页抓取可明确选择已有账号，保留原名称、顺序、外观和订阅记录。并发修改或删除时拒绝迟到保存。
3. DOM 绝对路径与局部文字识别容易失效，部分映射缺失仍可能显示成功。自动抓取账号每次重新进行语义识别，保留手动配置模式；若原有周期缺失，保留上次成功快照并明确提示不完整，禁止把余额作为完整用量更新。改进分散文案、进度条、周期及重置时间识别。

## 实现边界

- 会话按账号隔离，持久 Chromium partition 不依赖窗口生命周期；及时 flush 已有存储。平台令牌失效、撤销、验证码和人工登录仍须由用户处理，不保证永久有效，不绕过访问校验，不读取系统浏览器或 CLI 凭据。
- 已有账号定向抓取复用其会话。首页抓取并入已有记录时保留新会话的独立 partition 引用，不串用其他账号的会话。导入配置/备份不恢复浏览器会话引用。
- 自动匹配仅提供可见建议，不按平台或备注静默覆盖；检测到明确邮箱不一致则拒绝覆盖。用户可新建或选择正确账号。
- 自动语义识别为显式配置属性，兼容 1.2.0 自动抓取记录；自定义 selector 账号仍按配置读取。刷新失败保留旧值、原采集时间和旧数据标记。
- 时间优先采用接口绝对时间或网页明确时间。仅解析有明确时区的绝对时间、明确相对倒计时；按采集时刻固定相对时间。含糊周几、无时区日期或未提供的时间不推算；过期显示待平台确认，不自动增加 5 小时或 7 天。
- 不直接覆盖日常使用目录，不清理用户重复账号，不将账号、密钥、Cookie、原始网页或私有日志纳入源码、截图和发布包。实际配置诊断仅输出匿名结构统计。

## 实施顺序

1. 记录方案并读取匿名配置结构，建立问题回归用例。
2. 实现持久会话后台刷新、完整性校验和可恢复错误；增加账号绑定抓取保存与匹配选择。
3. 改进语义采集与明确重置时间，调整详情、编辑、抓取确认和用量展示文案，沿用 HAUI。
4. 三轮体验测试，每轮有独立记录，发现问题修复后重验。
5. 类型检查、生产构建、正式目录包、便携启动/更新回滚校验、完整 ZIP 与 SHA-256、一致性和本机 Defender 检查，整理交付。
