## 原生启动与更新的 9 个场景

1. 限制 PATH 的原生预检成功，无需系统开发运行时。
2. 删除运行文件时检测失败，给出明确缺件诊断。
3. 文件尺寸被改动时检测失败，给出完整包下载建议。
4. 中文、空格路径及不同工作目录下，经原生启动器完成 Electron UI 握手。
5. 普通原生辅助程序切换两个完整程序目录，保留旧版本。
6. 更新后实际解密原账号，UUID 与测试密钥保持一致。
7. 新版缺运行文件时，回滚到原程序并保留账号。
8. 新主体不创建窗口、也不发送就绪握手时，45 秒后超时；仅释放本次创建的进程树，完成回滚，原账号仍可读取。
9. 无效的跨机 DPAPI 浏览器密钥样本，启动器归档旧 runtime；界面可打开并进入账号保护/恢复状态，原账号文件不覆盖。

安装演练使用同一版本的两个独立正式二进制副本验证文件切换与回滚，不伪造公开的新版本。GitHub 元数据、下载摘要与线上版本检测的发布后证据单独保存到发布外层。

## 验证限制

1. 未在用户反馈的第二台电脑、独立 Windows 10、ARM64、多显卡或全部企业策略环境中实测。本机模拟故障不等同远端物理验收。
2. 未提供真实平台账号，本轮不宣称逐个平台实时数字、登录与接口变化均已验收。
3. 原生启动器和 Electron 主体均无发行者代码签名。Defender 本机扫描与源码复核不能保证商业杀软或 SmartScreen 没有误报/信誉提示；未向 VirusTotal 上传。
4. Windows 在程序执行之前施加的阻止无法由程序自身诊断；需要核对系统记录和文件哈希，不应关闭系统防护。
5. GitHub 网络、限流或权限错误会保留当前版并显示手动下载入口。其他进程持续占用文件或磁盘错误可能阻止自动回滚，原版和数据仍保留，并显示手动恢复位置。
6. 更新保留旧版程序目录；正常成功更新把完整 data 移入新版，旧版目录不再持有第二份实时 data。撤回版本时先关闭应用，把当前完整 data 一同迁回；重要数据建议先导出口令加密备份。

本版没有压缩壳、混淆、提权、驱动、进程注入、开机自启或后台服务。更新仅运行普通可见辅助进程，结束后退出。程序只读公开 GitHub 发布信息，发布凭据不进入客户端。
